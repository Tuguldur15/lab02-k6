## 3. SLO ба Threshold Тохируулсан Үндэслэл ба Тооцоолол

- **Baseline хэмжилт:** 5 VU ачаалалтай үеийн `p(95)` latency **326.93 ms** гарсан.
- **SLO `375 ms`-ийг `baseline 326.93 ms`-аас гаргасан тооцоолол:**
  - Абсолют нөөц / зөрүү: `375 ms - 326.93 ms = +48.07 ms`
  - Харьцангуй өсөлтийн нөөц: `(48.07 / 326.93) × 100% ≈ +14.70%` (`375 / 326.93 ≈ 1.1470`)
  - Суурь үзүүлэлт (`326.93 ms`) дээр сүлжээ ба серверийн богино хугацааны хэлбэлзлийг тооцсон ~`14.7%` (`+48.07 ms`) ачааллын буфер нэмж **375 ms** гэсэн SLO босгыг тогтоосон.
- **Threshold тохиргоо:** `http_req_duration` дээр `p(95) < 375ms`, харин алдааны түвшинг хязгаарлахын тулд `http_req_failed` дээр `rate < 0.01` (`< 1%`) тохируулсан.
- **Шалгалтын үр дүн:** `script.js` болон `script-stages.js` туршилтууд бүх threshold-ийг амжилттай давж **PASS** гарсан. Харин `script-fail.js` дээр босгыг санаатайгаар `p(95) < 50ms` болгож хатууруулахад бодит `p(95) = 244.1 ms` гарч threshold зөрчигдөн **FAIL** болж Quality Gate зарчим батлагдсан.

## 5. Дүгнэлт ба Ажиглалт

1. Grafana k6 хэрэгслээр зэрэгцээ виртуал хэрэглэгчийн тоог (VU) 5, 30, 100 түвшинд болон `5 → 30 → 100 → 0` stages горимоор ажиллуулж, `https://test.k6.io` веб байгийн хариу олгох хугацаа (latency) болон нэвтрүүлэх чадварыг (throughput) хэмжлээ.
2. 5 VU baseline хэмжилтээр `p(90) = 288.49 ms`, `p(95) = 326.93 ms` байсан бол 30 VU үед `p(90) = 233.1 ms`, `p(95) = 248.07 ms`, `44.18 req/s`, алдаа `0.00%` гарч тогтвортой ажилласан.
3. Ачааллыг 100 VU болгож өсгөхөд throughput `149.89 req/s` (`9,186` хүсэлт) хүртэл өссөн ч `p(95)` хугацаа `258.04 ms` хэвээр байж, алдааны хувь `0.00%` гарсан.
4. `5 → 30 → 100 → 0` stages туршилтаар нийт `3,190` хүсэлт (`52.13 req/s`) амжилттай гүйцэтгэж, `p(95) = 258.85 ms`, алдаа `0.00%` гарснаар ачаалал өсөх ба буурах үеийн тэсвэрлэлт батлагдлаа.
5. Гэсэн хэдий ч хамгийн удаан хүсэлтийн (`max`) үзүүлэлт 5 VU үед `992.77 ms` байснаас 100 VU үед `1.61s` болж нэмэгдсэн нь оргил ачааллын үеийн tail latency-г анхаарах шаардлагатайг харуулна.
6. `script-fail.js` туршилтаар `p(95) < 50ms` босго тавихад `p(95) = 244.1 ms` гарч threshold зөрчигдөн **FAIL** төлөв үүссэн.
7. Энэ нь автоматжуулсан pipeline эсвэл чанарын хяналтын шатанд SLO зөрчигдсөн тохиолдолд түгээлтийг зогсоох Quality Gate хэрхэн ажилладгийг практикт баталлаа.
8. Хэмжилтийн бүрэн гаралтыг `results/` хавтсанд хадгалснаар туршилтын үр дүнг дахин шалгах, баталгаажуулах нөхцөл бүрдсэн.
